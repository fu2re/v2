# BEATROOT — Game Design Document

> Рабочее название. `beat` (ритм) + `root` (корень) + `beetroot` (свёкла).
> Русское написание: **Битрут**.

**Версия:** 0.4 · **Дата:** 2026-08-15 · **Движок:** Godot 4.6 (Mobile renderer)

> Решения v0.4 — две кнопки и особые ноты, зелья, грейд экземпляра, уровни,
> скиллы, встречи, темповые ремиксы, интро — **реализованы** (§14, Фаза 6).
> Не сделаны: загадка во встречах и торговец на ферме с ротацией.

## 1. Питч

Ты растишь волшебный огород, выбираешь одного питомца-гуардиана и уходишь с ним в лес.
Лес — бесконечная лента полян, которую ты листаешь свайпом вверх, как TikTok.
На каждой поляне — **дэнс-баттл**: монстр танцует под музыку, ты тапаешь в такт.
Победил — угощаешь монстра фруктом со своей грядки, и он становится твоим другом.
Забег длится, пока у гуардиана есть здоровье. Потом — назад на ферму, к новым семенам.

**Одной строкой:** ферма-роглик, где сражаются танцем, а урожай — это друзья.

### Три столпа

| Столп | Что это | Зачем |
|---|---|---|
| **Ритм** | Каждое действие в игре — в такт музыке | Единый язык взаимодействия, от боя до полива грядки |
| **Дружба** | Монстры не убиваются, а приручаются накопительно | Ядро прогрессии без насилия и без фрустрации |
| **Поток** | Свайп-лента боёв без экранов загрузки и меню | Сессия начинается за 3 секунды и не имеет естественного конца |

### Ключевые решения (зафиксированы)

- Платформа: **мобильный, портрет**
- Бой: **20–30 секунд**, один короткий трек
- Отряд: **один гуардиан**; герой танцует рядом, но все статы на монстре
- Смерть: **мягкая** — теряется часть добычи забега, не коллекция
- Приручение: **шкала дружбы, ноль рандома**
- Бои: **без крови, дэнс-баттл**
- Ферма: реалтайм-таймеры + танец растению для ускорения

## 2. Аудитория и рамки

**Целевая аудитория:** дети 7+ и взрослые. Игра должна читаться ребёнком без чтения текста
(иконки, цвет, анимация) и при этом иметь глубину для взрослого (билды, редкость, тайминг).

**Из этого следуют жёсткие ограничения дизайна:**

1. **Ни одного бинарного провала.** Промах не отнимает прогресс, а замедляет его.
   Ребёнок никогда не должен услышать «ты не получил монстра».
2. **Ноль насилия.** Монстры не получают урон — они «сбиваются с ритма». Победа =
   монстр остановился и слушает. Нет крови, нет смерти, нет оружия.
3. **Читаемость на маленьком экране.** Крупные силуэты, высокий контраст ноты и фона.
4. **Без таймерного давления и без манипулятивных механик.** Никаких «вернись через 4 часа
   или урожай сгниёт». Урожай не портится никогда.
5. **Play-to-win.** Всё, что влияет на геймплей, добывается игрой. Реальные деньги — только косметика.

## 3. Основной цикл

```
        ┌──────────────────────────────────────────────────┐
        │                                                  │
        ▼                                                  │
   ┌─────────┐    выбор     ┌──────────┐   свайп ↑   ┌──────────┐
   │  ФЕРМА  │─ гуардиана ─▶│  ЛЕС     │───────────▶│  ПОЛЯНА  │
   │         │  и фруктов   │  (лента) │◀───────────│  (бой)   │
   └─────────┘              └──────────┘здоровье>0 └──────────┘
        ▲                                                  │
        │              возврат: здоровье = 0                   │
        │              или выход по своей воле             │
        └──────────────────────────────────────────────────┘
```

### Петли по масштабу

| Петля | Длительность | Содержание |
|---|---|---|
| Микро | 20–30 сек | Один дэнс-баттл: серии, атаки, щиты |
| Мини | 3–8 мин | Забег: 6–15 полян, растущая сложность, решение «идти дальше или выйти» |
| Средняя | сессия 10–20 мин | Ферма → забег → трата добычи → новый забег |
| Макро | недели | Коллекция гуардианов, редкие семена, снаряжение, сезонная косметика |

**Момент напряжения** — в конце каждой поляны. Здоровье на исходе, но следующая поляна даёт
больше награды. Свайпнуть ещё раз или уйти с тем, что есть? Это главное решение игры,
и оно повторяется десятки раз за забег.

## 4. Дэнс-баттл (ядро)

### 4.1 Раскладка экрана (портрет)

```
┌─────────────────────────┐
│ Ростик · Редкий  84/160 │  ← имя монстра и грейд рядом со шкалой
│ ▓▓▓▓▓▓▓░░░ Настрой      │
│      МОНСТР (танцует)   │
├─────────────────────────┤
│                         │
│    ↓ ноты падают ↓      │  ← средняя треть: дорожка нот
│      ●───●───★          │  ← ноты одной серии соединены линией
│                         │
├─────────────────────────┤
│  ═══ ЛИНИЯ УДАРА ═══    │  ← особые ноты падают чуть левее центра, обычные — чуть правее
│ [ ОСОБАЯ ] [ ОБЫЧНАЯ ]  │  ← две зоны тапа: левая и правая половина низа
│   ГЕРОЙ      ГУАРДИАН   │  ← оба танцуют, снаряжение видно на гуардиане
│ Щит 13/40  Здоровье 78/100 │
└─────────────────────────┘
```

**Грейд подписывается только если он выше обычного.** Слово «Обычный» ничего
не сообщает и лишь занимает место — редкость должна бросаться в глаза именно
тогда, когда она есть.

**Герой и гуардиан танцуют внизу.** Они двигаются на каждую долю, кивают
на попадание и делают рывок на атаке. Это единственное место, где игрок видит,
что снаряжение на гуардиане действительно надето, а не записано в таблице.

Зона тапа — **две крупные половины нижнего блока**, а не мелкие кнопки.
Правая — **обычный бит**, левая — **особый бит**. Больше целей нет: игрок
думает про «когда» и про один бинарный выбор «обычное или особое». Для
интуитивности дорожка подсказывает ответ заранее: обычные ноты падают чуть
правее центра, особые — чуть левее, то есть нота сама съезжает к своей кнопке.

На десктопе (для проверки игры, не для игроков): стрелка вправо — обычный бит,
стрелка влево — особый.

### 4.2 Типы нот

Два входа — обычный и особый — и пять типов нот поверх них:

Столбец «в чарте» — это имя типа в JSON и в `NoteType`. Он здесь не для
полноты: пока связь не была записана, зелье сидело на типе `snack`, и по
названию этого нельзя было угадать. Когда зелья упразднили, ноту переименовали
в `heavy` во ВСЕХ трёхстах чартах разом — оставить чужое имя за тяжёлой атакой
значило бы завести ложь, с которой придётся жить годами.

| Нота | В чарте | Вид | Кнопка | Действие | Комментарий |
|---|---|---|---|---|---|
| **Бит** | `beat` | ● голубой круг | обычная | Копит серию. Урона НЕ наносит | Основа, ~70% нот |
| **Атака** | `attack` | ★ золотая звезда | **особая** | Единственный источник урона по Настрою | Только в конце серии |
| **Скилл** | `skill` | ◆ розовый ромб | **особая** | Спецдвижение гуардиана (§4.2.4) | По кулдауну, ~5%; промах бьёт больнее обычного |
| **Щит** | `shield` | ⬡ синий щит | **особая** | Блокирует атаку монстра, чинит свой щит | Телеграфируется; обычной альтернативы НЕТ |
| **Тяжёлая атака** | `heavy` | ❗ красная шипастая звезда | **особая** | Блокирует крит; пропущенная бьёт ВЧЕТВЕРО больнее | Бывшая нота-зелье: зелий в игре нет (§4.2.3) |

Правила соответствия «нота ↔ кнопка»:

- **Атака монстра (нота-щит) — всегда особый бит без альтернативы.** Прожал
  особую кнопку — блок; прожал обычную или промолчал — атака дошла.
- **Зелье — единственная нота с выбором.** Особая кнопка выпивает зелье
  (тратится предмет, возвращается здоровье), обычная — засчитывает обычный бит
  и сберегает зелье. Экономить или лечиться — микрорешение прямо в ритме.
- **Если зелий в инвентаре нет, нота-зелье не ставится вовсе** — на её месте
  обычный бит. Игра никогда не предлагает нажать то, что не сработает.

### 4.2.1 Серии и атака

**Обычные биты не бьют монстра.** Они собирают серию. Урон наносит только
атакующая нота в её конце — и только если серия пройдена **без единого промаха**.

Изначально каждое попадание сбивало Настрой. От этого отказались: при таком
устройстве бой сводился к «тапай почаще», а точность влияла лишь на скорость.
Теперь ошибка в середине связки обесценивает её целиком, и игрок ведёт фразу,
а не долбит по экрану.

Правила разметки:

- Атака **завершает** серию: следующая нота начинает новую
- Перед атакой обязаны быть минимум **3 ноты** без длинной паузы
- Атака **никогда не стоит сразу после паузы** — серии перед ней тогда нет
- Пауза длиннее половины такта обрывает серию

Что видит игрок:

- Ноты одной серии **соединены линией** — видно, где связка началась
- Промах в серии **гасит звезду в серый**: сразу понятно, что удар уже
  не сработает, и не надо гадать
- Удавшаяся атака даёт **вспышку экрана и рывок монстра** — связь «вёл чисто →
  прилетело» обязана читаться мгновенно

**Щит — вторая механика напряжения.** Монстр за 2 такта до атаки делает заметный
замах и подсвечивается. Пропущенный щит бьёт сильнее всего остального (§4.4),
а принятый — чинит собственный щит игрока.

### 4.2.2 Исход боя показывается НА МЕСТЕ

Отдельного экрана результата нет. Бой заканчивается там же, где шёл, —
и разница между двумя исходами читается без слов:

| Исход | Что видно |
|---|---|
| **Победа** | Монстр падает набок, вместо глаз крестики, надпись «Наплясался!» |
| **Не победа** | Монстр убегает вбок и растворяется, надпись «Убежал…» |

Различие обязано быть однозначным, потому что от него зависит доступность
приручения: подружиться можно **только с побеждённым** (§6.1). Ребёнок должен
понять причину сам, не читая объяснения.

Экран боя остаётся до свайпа: игрок сам решает, когда идти дальше.

**Между победой и угощением есть пауза.** Поверх лежащего монстра появляется
короткий итог: сколько серебра, что в сундуке, вырос ли уровень, — и только
по нажатию открывается угощение. Сначала было иначе: экран приручения выезжал
мгновенно, и игрок не успевал увидеть ни падающего монстра, ни своей добычи.
Награда, которую не заметили, — это не награда.

### 4.2.3 Тяжёлая атака

**Зелий в игре нет.** Они были нотой с выбором — особой кнопкой выпить,
обычной сберечь, — и выбор этот принимался за долю секунды посреди фразы,
то есть не принимался вовсе: игрок жал что успевал. Лечение переехало
к костру (§8.2.3), где решение «лечиться или беречь угощение» обдумывают
спокойно и где оно чего-то стоит.

Освободившаяся нота стала **тяжёлой атакой монстра**. Блокируется той же
особой кнопкой, что и обычная, но пропущенная бьёт **вчетверо** больнее.
Особая нота обязана ЧУВСТВОВАТЬСЯ особой, а не отличаться одним силуэтом:
рисуется она красной шипастой звездой с восклицательным знаком, а цифра
пропущенного крита вылетает вдвое крупнее обычной и красным.

**Ни один удар не заканчивает забег с полного здоровья.** Множители
перемножаются — ×4 за крит и ×5 за легендарный грейд давали удар на 300
при 172 здоровья, то есть смерть с ПЕРВОГО пропуска у полностью прокачанного
гуардиана. Один удар не может снять больше 90 % запаса здоровья: пропустил
крит — осталась полоска, а не экран поражения. Второй пропуск уже убивает,
поэтому милость не превращает крит в бесплатный. Порог задан константой
`MAX_BLOW_SHARE` и сторожится `tests/test_battle.gd`.

В чартах она называется `heavy`. Триста готовых чартов переименованы разом:
оставить имя `snack` за тяжёлой атакой значило бы завести ложь, с которой
придётся жить годами — предыдущая такая уже стоила путаницы.

### 4.2.4 Скилл — спецдвижение гуардиана

Скилл-нота запускает спецдвижение, определяемое **стихией гуардиана**, —
пять стихий, пять эффектов:

| Стихия | Спецдвижение | Эффект |
|---|---|---|
| Камень 🪨 | Топот | следующая удавшаяся атака ×1.5 |
| Солнце ☀️ | Вспышка | +6 к щиту |
| Листва 🍃 | Дыхание леса | +5 к здоровью |
| Искра ✨ | Разряд | +5 к комбо |
| Ветер 🌬️ | Порыв | окна тайминга ×1.25 на следующие 4 такта |

Скилл ставится в чарт по кулдауну (§10.2). Промах по скиллу наказывается
сильнее обычного промаха — 6 урона против 3 (§4.4): особая нота требует
особого внимания, иначе левая кнопка ничем не отличалась бы от правой.
Эффекты нарочно маленькие и мгновенные: скилл — приправа к бою,
а не вторая боевая система.

### 4.3 Оценка тайминга

| Оценка | Окно | Эффект |
|---|---|---|
| Perfect | ±50 мс | Полный эффект, комбо +1, яркий визуал |
| Good | ±110 мс | 60% эффекта, комбо +1 |
| Late/Early | ±180 мс | 30% эффекта, комбо сохраняется |
| Miss | вне окна | Эффекта нет, комбо сброс, **урон в щит** |
| Тап мимо всякой ноты | — | Серия испорчена и комбо сброшено; с четвёртого подряд ещё и урон |

**Тап в пустоту не бесплатен, а долбёжка — тем более.** Правило состоит
из двух половин, и обе нужны.

Первая: любой лишний тап рвёт серию, а без чистой связки атака не проходит
вовсе (§4.2.1). Этого казалось достаточно, но оказалось мало: рваная серия
отнимает у игрока его СОБСТВЕННЫЙ урон, а здоровье не трогает. Живой отчёт:
«могу просто всегда жать вправо и не получать урона» — и так и было. Долбить
правую кнопку двадцать раз в секунду было строго выгодно: каждый бит попадал
в своё окно сам собой, девятнадцать промахов между ними не стоили ничего,
и «когда» переставало иметь значение — то есть ритм-игра отменялась.

Вторая: **три лишних тапа ПОДРЯД прощаются, каждый следующий стоит здоровья.**
Счёт обнуляет любая взятая нота. Разница между «потыкал в экран» и «долблю
кнопку» именно в этом: первое обрывается попаданием, второе — нет. Ребёнок,
впервые увидевший экран, по-прежнему ничего не платит; непрерывная долбёжка
съедает щит за несколько секунд. Цена мала намеренно — она не должна убивать,
она должна сделать спам ХУЖЕ игры по такту, и этого достаточно.

Сторож — `tests/test_fair_play.gd`: точное прохождение чарта побеждает
с полным запасом, оно же с долбёжкой между нотами проигрывает.

Окна расширяются снаряжением (пояс) и сужаются на высокой сложности.

Промах бьёт по щиту, а не по здоровью, — см. §4.4. Раньше здесь было записано,
что обычный промах не наказывает вовсе; от этого отказались, потому что игра,
где ошибка ничего не стоит, перестаёт быть ритм-игрой. Щит взял на себя роль
прощения, и наказание вернулось без риска фрустрации.

**Комбо:** ×1 → ×1.5 (10 нот) → ×2 (25) → ×3 (50). Комбо умножает урон атакующих нот
и главная награда за мастерство.

**Сколько длится бой.** Настрой монстра подобран так, чтобы **чистое прохождение
трека выбивало его к концу мелодии**, а не на середине. Отсюда прямое следствие,
которое легко потерять: атак в чарте немного (7–10), и промах, испортивший серию,
стоит целой атаки. Первая сборка на настоящих чартах этого не учла — монстра
нельзя было добить даже идеальной игрой, и бой заканчивался «убежал» всегда.

**Настрой вида связан с его чартом, а не назначается отдельно.** У каждого вида
своя мелодия, и число атакующих нот в ней разное: у латины их вчетверо меньше,
чем у фолка. Значит и Настрой обязан быть разным — иначе один и тот же
«крепкий» монстр оказывается непобедимым просто потому, что ему досталась
разреженная аранжировка. Это ровно та ошибка, которую поймал живой прогон.
Проверяется тестом на проходимость по каждому виду.

Неровная игра компенсируется прогрессией, а не поблажками в бою: с уровнем
и изученностью вида тот же монстр падает и при 85% попаданий (§6.5). Но чем
ниже точность, тем слабее помогает прокачка: рваные серии обнуляют атаки
целиком, и никакой множитель к нулю не применяется.

### 4.4 Шкалы

Три шкалы, и разделение между двумя нижними принципиально.

| Шкала | Чья | Живёт | Восстанавливается |
|---|---|---|---|
| **Настрой** | монстра | один бой | нет, обнулился — победа |
| **Щит** | игрока | **весь забег** | только нотами-щитами |
| **Здоровье** | игрока | весь забег | только у костра и зельями |

Щит сначала обновлялся на каждой поляне. Отказались: забег — испытание
на выносливость, и буфер, восстанавливающийся сам, снимал всё напряжение
между боями. Теперь оба ресурса сквозные, а разница между ними в том,
ЧЕМ они чинятся: щит — навыком прямо в бою, здоровье — только привалом.

**Щит — это буфер прощения.** Урон идёт сначала в него и только потом в здоровье.
Пока щит держится, промахи стоят внимания, но не прогресса. Здоровье трогается,
только когда буфер выбит полностью.

Такое устройство разрешает противоречие, которое иначе не решается: промахи
обязаны что-то значить, иначе ритм-игра превращается в фон, — но ребёнок 7 лет
не должен терять забег из-за пяти неточных тапов. Щит даёт право ошибаться
несколько раз подряд и чинится тем же навыком, который его тратит.

**Нота-щит поэтому не только угроза, но и возможность:** попадание по ней
восстанавливает часть буфера. За щитами следят вдвойне.

Цена промахов:

| Событие | Урон |
|---|---|
| Промах по обычной ноте | 3 |
| Промах по скиллу | 6 |
| Пропущенный щит (атака дошла) | 10 |
| Попадание по щиту | **+2 к щиту** |

Числа в таблице — для **обычного** монстра. Всё, что он наносит, умножается
на его ×Удар (§6.3): у эпического тот же пропущенный щит стоит уже 38.

**Щит чинится по копейке, и это намеренно.** Он расходуемый буфер на весь
забег, а не возобновляемый ресурс: пока попадание возвращало восемь, буфер
чинился быстрее, чем тратился, и забег переставал быть испытанием
на выносливость. По той же причине костёр возвращает всего 10 здоровья —
это передышка, а не кнопка «начать сначала».

Здоровье на нуле → гуардиан устал, забег окончен (мягкая смерть, §8.4).

### 4.5 Монстр как танцор

Монстр не «атакует» — он **ведёт танец**. Его анимация синхронизирована с треком:
он двигается на каждую четверть, а его «атаки» — это эффектные па, которые надо
переждать за щитом. Визуально это батл двух танцоров, а не драка.

Каждый монстр имеет **танцевальный паттерн** — последовательность из 4–8 движений,
привязанную к тактовой сетке. Паттерн определяет, когда придут ноты-щиты.
Игрок, увидевший монстра второй раз, уже узнаёт его ритм — это и есть кривая обучения.

## 5. Стихии (система типов)

Пять природных характеров. **Игроку они показываются как стихии, а не как жанры:**
музыкальный жаргон ничего не говорит семилетнему, а «Камень бьёт Солнце» понятно
без объяснений. Внутри кода за каждой стихией по-прежнему закреплена своя
аранжировка трека — отсюда и вся выгода для музыкального пайплайна.

| Стихия | Аранжировка | Характер | Бьёт | Уязвима к |
|---|---|---|---|---|
| **Камень** 🪨 | рок | Мощные редкие удары | Солнце | Искру |
| **Солнце** ☀️ | диско | Ровный поток нот | Листву | Камень |
| **Листва** 🍃 | фолк | Долгие фразы | Искру | Солнце |
| **Искра** ✨ | электро | Быстрые синкопы | Камень | Листву |
| **Ветер** 🌬️ | латина | Нейтральный | — | — |

Преимущество = ×1.4 к урону по Настрою и ×0.7 к получаемому урону. Ветер нейтрален —
без преимуществ и слабостей, для универсальных гуардианов.

Ветру достался не хип-хоп, как задумывалось сначала, а **латина**: на синтезе,
которым делаются треки, хип-хоп выходил почти пустым — разреженный бит
и длинный саб, — а «почти пустой» для ритм-игры означает «не по чему попадать».
Нейтральный характер стихии латина держит не хуже.

**Практическое следствие для музыки:** один хороший мелодический мотив можно
переаранжировать в 5 жанрах и 3 темповых ступенях (§10.1.1) — до ×15 контента
с одной удачной мелодии.

## 6. Приручение

### 6.1 Шкала дружбы

**У каждой пары «вид + грейд» своя постоянная шкала дружбы.** Она не сбрасывается
никогда — ни при смерти, ни между забегами.

| Событие | Прибавка к дружбе |
|---|---|
| Победил монстра этого вида и грейда | +10 |
| Победил с полным комбо (S-ранг) | +15 |
| Угостил любимым фруктом | +35 |
| Угостил нелюбимым фруктом | +10 |
| Не угостил (нет фруктов) | +0 (но победа уже засчитана) |

**Шкалы грейдов независимы.** Дружба 20/100 с обычным Ростиком не приближает
редкого: тому копить свои 200 с нуля. Порог растёт с грейдом —
100 / 150 / 200 / 250 / 300 / 400 (§6.3).

Правило одно: победа над экземпляром заполняет ЕГО шкалу, и когда та полна,
экземпляр **гарантированно** присоединяется — без броска кубика и без
«не повезло». Экран: монстр подходит, обнимает героя, идёт с ним.

**Приручать можно только по порядку, снизу вверх.** Необычный открывается
после обычного, редкий — после необычного, и так до легендарного. Перепрыгнуть
ступень нельзя, даже если шкала полна: удачная встреча с легендарным
не должна отдавать вершину коллекции тому, кто ни разу не танцевал
с этим видом попроще.

При закрытой ступени дружба **не копится вовсе**, и шкалы на карточке нет.
Раньше копилась «про запас»: полоска ползла, фрукты списывались, а приручение
всё равно не наступало. Двигать шкалу, с которой ничего нельзя сделать, —
то же самое, что выбрасывать угощение. Игра обязана назвать недостающую
ступень: пропавшая шкала без объяснения читается как поломка.

С тем, кто **уже в коллекции**, дружиться заново не с кем: шкалы у него нет,
угощение после боя не предлагается, и бой с ним идёт за опытом и добычей.
Драться с приручённым при этом можно — кнопка боя на месте.

**Почему так, а не одна шкала на вид:** приручить редкого должно быть трудно
именно по-настоящему, а не «дособрать хвост» на лёгких обычных встречах.
Иначе игрок фармит самого безопасного монстра вида и получает легендарного,
ни разу не встретившись с трудным. Независимые шкалы делают каждый грейд
отдельной целью — и ровно поэтому редкость остаётся редкостью.

**Почему при этом нет фрустрации:** ребёнок всегда видит движение полоски
вперёд. Худший исход встречи — «стало ближе», а не «не получилось».

**Ферма — не украшение, а основная дорога.** Здесь легко обмануться: десять
побед по 10 очков закрывают обычную шкалу, и кажется, что подраться —
нормальный путь. Это не так, и разница считается в один шаг: виды в ленте
равновероятны, их пять, и десять побед НАД ОДНИМ видом означают полсотни
боёв вперемешку с остальными. С учётом того, что боем занята примерно
половина полян, — около восьмидесяти полян, три полных забега без единого
нового друга.

Путь через ферму короче на порядок: одна встреча плюс два спелых любимых
фрукта (35 × 1.6 = 56 каждый) закрывают ту же шкалу. Восемь полян вместо
восьмидесяти.

Отсюда два следствия для дизайна, оба обязательные:

- игра должна **называть** любимый фрукт на карточке поляны и на экране
  угощения — иначе короткая дорога остаётся невидимой, и ребёнок идёт
  в гринд, не зная, что его можно не проходить;
- удлинять шкалы или резать прибавку от фруктов нельзя, не пересчитав
  это соотношение заново.

Оба числа считает `tests/test_child_pace.tscn` и печатает при каждом прогоне.

### 6.2 Любимый фрукт

Монстр **визуально показывает**, чего хочет — над ним висит иконка фрукта, ещё до боя,
прямо на поляне. Игрок видит это до свайпа и может решить, стоит ли останавливаться.

Это превращает ферму в осмысленный выбор: «мне нужны Барабанные Ягоды, потому что
их любит Бас-Медведь, а до него осталось 30 дружбы».

### 6.3 Редкость

**Грейд принадлежит экземпляру, а не виду.** Один и тот же Ростик на поляне
может оказаться и обычным, и легендарным: грейд роллится при генерации встречи
по таблице долей, а глубина забега сдвигает веса к редким. Все веса и сдвиг —
настройка в [drop_tables.json](data/drop_tables.json), не код.

| Грейд | Цвет | Порог дружбы | Доля на поверхности | Открывается с поляны | ×Статы |
|---|---|---|---|---|---|
| Обычный | белый | 100 | 90% | 1 | 1.0 |
| Необычный | зелёный | 150 | 9% | 1 | 1.15 |
| Редкий | синий | 200 | 1% | 1 | 1.3 |
| Уникальный | фиолетовый | 250 | — | 5 | 1.5 |
| Эпический | золотой | 300 | — | 12 | 1.7 |
| Легендарный | тёмно-золотой, переливается | 400 | — | 20 | 2.0 |

**У поверхности почти всё обычное, и это не приблизительно.** Первые поляны —
девять обычных из десяти; старшие грейды не «редко выпадают», а не существуют
там вовсе, пока игрок не зайдёт глубже. Без такого порога линейный сдвиг долей
выдавал уникального уже на второй поляне: новичок утыкался в непроходимый бой,
не успев понять правила. Редкое — награда за то, что зашёл дальше, а не
случайность на входе.

Колонка ×Статы — **одна и та же для врага и для твоего гуардиана**: она
масштабирует Настрой дикого экземпляра и базовые статы приручённого.
Легендарный примерно вдвое крепче обычного того же уровня — заметно,
но не пропасть.

**Урон монстра растёт по ОТДЕЛЬНОЙ, куда более крутой шкале:**

| Грейд | ×Крепость | ×Удар |
|---|---|---|
| Обычный | 1.0 | 1.5 |
| Необычный | 1.15 | 1.9 |
| Редкий | 1.3 | 2.4 |
| Уникальный | 1.5 | 3.1 |
| Эпический | 1.7 | 4.0 |
| Легендарный | 2.0 | 5.0 |

Пока обе величины шли по одной кривой, эпический бил лишь чуть сильнее
обычного, и грейд читался подписью в углу, а не тем, что происходит на экране.
Теперь разница видна по цене ошибки: пропущенных атак обычного игрок выдержит
около семи, эпического — три.

**Пол лестницы удара поднят, потолок оставлен на месте.** По живой игре
обычный монстр не кусался вовсе: бой с ним был формальностью, и попадать
в такт было незачем — отсюда 1.0 → 1.5. Потолок при этом остался на 5.0,
потому что он перемножается с ×4 за крит (§4.2.3): растянутая до 7.5
лестница убивала полностью прокачанного гуардиана с одного пропуска.
Широкий разрыв между грейдами и высокий пол несовместимы, и выбран пол —
низкие грейды игрок встречает в сто раз чаще эпических. Разрыв обычный →
эпический сторожится тестом на 2.5 раза (`tests/test_fair_play.gd`).

Третья ось сложности — темп: чем выше грейд, тем быстрее ремикс трека
(§10.1.1). Крепость, злость и скорость растут по-разному, и вместе они
и делают редкую встречу событием.

Приручить обычного легко на любой глубине: его доля никогда не падает ниже
пола (конфиг), порог дружбы низкий, темп спокойный. Высокий грейд труднее
по трём независимым осям сразу — реже встречается, требует своей отдельной
шкалы дружбы (§6.1) и быстрее танцует. Но шанс приручения по-прежнему
не существует как понятие: заполнил шкалу — забрал гарантированно.

Коллекция хранит **экземпляры**: у игрока могут жить обычный и редкий Ростик
одновременно, каждый со своим уровнем (§6.5) и своим снаряжением.

**Чем выше грейд, тем интереснее нарисован монстр.** Легендарный — единственный
переливающийся: это должно быть видно ещё на карточке поляны, до боя.

Спрайты хранятся как `art/monster/{вид}_{грейд}.png`. Пока грейд не нарисован,
показывается **максимальный доступный** спрайт вида: игра остаётся играбельной
на неполном арте, а картинка сама становится точнее по мере рисования,
без единой правки кода.

### 6.4 Опыт против вида

Каждая встреча с видом добавляет урона по нему — до потолка.

Хранится **отдельно от дружбы** намеренно. Дружба — про то, насколько монстр
к тебе расположен; опыт — про то, насколько ты изучил его повадки. Слей их, и
игрок наказывался бы за приручение любимого вида: приручил — и растить нечего.

Опыт начисляется **и за проигранный бой**: повадки ты изучил в любом случае,
а откат прогресса за неудачу — ровно то, чего игра для детей делать не должна.

То же правило распространяется и на **уровень гуардиана** (§6.5): за убежавшего
монстра он получает половину опыта. Без этого новичок запирался намертво —
живой прогон показал ровно это: бой с незнакомым видом обязателен, добить его
пока нечем, а гуардиан от таких боёв не рос, то есть не стал бы сильнее никогда.
Танцевал — значит учился.

Потолок обязателен: без него сотая встреча превращала бы бой в формальность,
а редкие виды обесценивались бы у того, кто их фармит.

### 6.5 Прогрессия силы — явная модель

Долгая прогрессия стоит на двух опорах: **уровни экземпляра + снаряжение**.
Эволюции нет и не будет: монстр, которого ты приручил, остаётся собой —
не меняет облик, а растёт в силе. Ребёнок привязывается к конкретному
существу, и подменять его «взрослой формой» значило бы отнимать друга.

**Уровни.** Каждый приручённый экземпляр имеет уровень **1–10**.
Опыт экземпляру дают два занятия — и оба уже есть в петле:

| Источник опыта | Кто получает | Сколько |
|---|---|---|
| Победа в забеге | гуардиан, который дрался | база + бонус за грейд противника и S-ранг |
| Угощение фруктом на ферме | кого угощаешь | по тиру и качеству фрукта; любимый — вдвое больше |

Каждый уровень — **+8% к базовым статам**; 10-й уровень ≈ ×2 к первому.
Кривая опыта и точные прибавки — [progression.json](data/progression.json).

Кормление решает две задачи сразу: фрукты остаются нужными после того, как
вид приручён (раньше шкала капала в потолок — и ферма выпадала из петли),
а прокачка любимца происходит тем же жестом, что и приручение. Один язык
на всю игру: дружишь — угощаешь.

Полная лестница силы:

| # | Источник | Рост | Предел |
|---|---|---|---|
| 1 | Уровень экземпляра | +8% к статам за уровень | ×2 на 10-м уровне |
| 2 | Грейд экземпляра (§6.3) | ×1.0 → ×2.0 к базовым статам | легендарный |
| 3 | Снаряжение, 3 слота (§9) | урон, здоровье, окна, защита | лучшие вещи — [items.json](data/items.json) |
| 4 | Опыт против вида (§6.4) | урон по конкретному виду: +4% за встречу | +60% (15 встреч) |
| 5 | Выбор стихии под встречу (§5) | ×1.4 к урону при преимуществе | — |
| 6 | Мастерство игрока (§4.3) | комбо до ×3, чистые серии, S-ранг | — |

Итого легендарный экземпляр 10-го уровня в лучшем снаряжении примерно
вчетверо сильнее стартового обычного — а дальше растут коллекция
и мастерство. Победа над монстром уже приручённого вида осмысленна всегда:
опыт — гуардиану, дружба — шкале ЭТОГО грейда, сундук — в сумку.

## 7. Ферма

### 7.1 Общая логика

Ферма — база между забегами. Сетка грядок (стартово 4, расширяется до 16).
Растения зреют **в реальном времени, в том числе оффлайн**. Урожай не портится и не сгорает.

| Тир семени | Время роста | Дружба за плод | За час | Роль |
|---|---|---|---|---|
| Обычное | 10 мин | 35 | 210 | активная сессия |
| Необычное | 30 мин | 60 | 120 | «схожу и вернусь» |
| Редкое | 2 ч | 95 | 48 | «зайду вечером» |
| Эпическое | 8 ч | 140 | 18 | ставится перед сном |

Дружба указана для ЛЮБИМОГО фрукта вида; нелюбимый считается от 10
по той же лестнице тиров.

**Разброс щедрости ×4 против разброса времени ×48 — так и задумано.**
Ожидание в ферме покупается не эффективностью за час, а размером одного
урожая: за ночь никто не соберёт десятиминутную грядку сорок восемь раз.
Быстрые культуры кормят активную сессию, долгие — сон и школу.

Верхний плод обязан закрывать обычную шкалу дружбы **в одиночку** (140 против
порога 100). «Посадил перед сном — проснулся с новым другом» и есть то, ради
чего вообще ждут восемь часов; прибавка вместо события ожидание не окупает.

Лестница сторожится `tests/test_farm.tscn`: каждый следующий тир обязан быть
и щедрее, и дольше предыдущего. Проверка появилась не зря — до неё редкий
инжир давал РОВНО столько же дружбы, сколько необычная сливка, при вчетверо
большем времени роста и вдвое большей цене. Такой предмет не сажают никогда,
и увидеть это можно было только посчитав.

### 7.2 Качество урожая

**Качество фрукта** (Обычный / Сочный / Идеальный) — множитель к прибавке
дружбы: ×1 / ×1.3 / ×1.6. Задаёт его **сорт семечка**: чем дороже и дольше
растёт семя, тем лучше плод.

| Сорт семечка | Качество плода |
|---|---|
| 0 — дикая ягода из куста | Обычный |
| 1–2 — покупное семя | Сочный |
| 3 — редкое семя | Идеальный |

**Здесь была мини-игра «танец растению»** — ритм-фраза на 8 битов, ускорявшая
рост и дававшая качество. Убрана: она не работала, а на экране огорода была
единственным местом, где ритм-механика жила вне боя, — и потому не тянула
ни как ритуал, ни как ритм-игра.

Качество переехало на сорт семечка, а не исчезло: иначе система качества
осталась бы с одним значением, а вместе с ней подешевел бы путь через ферму
(§6.1), где два спелых любимых фрукта закрывают шкалу дружбы. Новой механики
взамен не выдумано намеренно — качество и так уже есть чем заслужить:
хорошее семечко надо найти в лесу или купить.

### 7.3 Семена

- **Базовые** — покупаются за серебро в лавке усадьбы (§8.2.2), всегда доступны
- **Дикие** — падают с фруктовых кустов на полянах леса; единственный способ получить
  новые виды культур

Дикие кусты — отдельный тип поляны в ленте. Это связывает лес и ферму в замкнутый контур:
идёшь в лес → находишь семена → растишь фрукты → приручаешь монстров → идёшь дальше в лес.

**Куст даёт СЕМЯ, а плод с него — редкая удача.** Семя падает всегда: за ним
к кусту и подходят. Готовый плод — только в пятнадцати случаях из ста и ровно
один (числа в [drop_tables.json](data/drop_tables.json), `wild_bush.yield`).
Иначе контур рвётся в самом важном месте: если фрукты можно набрать в лесу,
грядка становится необязательной, а вместе с ней и всё ожидание урожая,
на котором держится ритм возвращений.

Вид фрукта выбирается равновероятно — это нужно СЕМЕНАМ, иначе редкие
культуры не открыть вовсе. На готовый плод то же правило накладывается
поверх броска, поэтому золотое яблоко с куста выпадает примерно раз
на тридцать кустов, а не с каждого.

### 7.4 Усадьба — двор, из которого расходятся места

Ферма — не отдельный экран, а одно из мест **усадьбы**. Главный экран между
забегами — нарисованный двор, на котором стоят постройки, и каждая ведёт
в своё место:

| Постройка | Место | Что там |
|---|---|---|
| Огород | ферма | грядки и посадка |
| Коллекция | витрина существ | все виды и грейды, снаряжение, угощение (§7.5) |
| Инвентарь | сумка | семена, фрукты, зелья, снаряжение |
| Магазин | торговец | покупка за серебро; отсюда же вход в наряды за золото |
| В путь | забег | свайп-лента полян |

Названия намеренно бытовые, а не сказочные: «Амбар» и «Дом защитников»
приходилось расшифровывать, а семилетний читает вывеску один раз и должен
сразу понять, что за ней. «В путь» вместо «Лес» — потому что это не место,
а действие: единственная кнопка на экране, которая начинает игру.

Постройки стоят по местам ландшафта, а не рядами: изба слева, прилавок
по центру, амбар справа, лес в глубине, грядки на переднем плане внизу.
Ряды выглядели списком иконок, а не двором.

Границы постройки берутся по НЕПРОЗРАЧНЫМ пикселям, а не по квадрату
текстуры. Постройки нарисованы в квадрате 128×128 с широкими полями,
и по полной коробке получалось два вранья сразу: кнопка ловила клики
по пустому воздуху рядом с домиком, а подпись огорода уезжала так низко,
что садилась на соседний прилавок. Подпись, которой не хватает места снизу,
поднимается над постройкой — безымянных построек быть не должно.

**Нажимается сам домик, а не кнопка со словом.** Ребёнок семи лет узнаёт
огород по грядкам быстрее, чем прочитает слово «огород» (§2.3). Подпись
под постройкой всё же есть — для взрослого и для того, кто картинку
не разобрал, — но идёт второй. Постройка под пальцем светлеет и чуть
подрастает: без отклика непонятно, что двор вообще нажимается.

Двор — **единственная развилка**: раньше каждый экран знал про все остальные
и «назад» означало разное в зависимости от того, откуда пришёл. Теперь из
любого места ведёт одна дорога — во двор, а оттуда куда угодно.

У каждого места **своя нарисованная страничка**: огород, коллекция,
инвентарь и магазин отличаются фоном, а не только списком. Вход должен ощущаться
переходом В МЕСТО. Фон приглушается, потому что поверх него лежит текст —
та же причина, по которой притемняется фон боя (§11.1.1).

Пока постройка не нарисована, её место остаётся доступным: во дворе стоит
временный предмет, а не пустота. Игра не должна ждать арта, чтобы работать.

### 7.5 Коллекция — витрина всех существ

Коллекция показывает игру ЦЕЛИКОМ: строка на вид, колонка на грейд,
слева направо от обычного к легендарному. Одним взглядом видно, сколько
всего существ в игре, что уже открыто и чего не хватает — до этого экран
был списком приручённых, и вопрос «а сколько ещё осталось» ответа не имел.

Три состояния клетки:

| Состояние | Как выглядит | Когда |
|---|---|---|
| Закрыт | чёрный силуэт | ни разу не побеждён |
| Открыт | обычный скин, чуть приглушён | побеждён хотя бы раз |
| В коллекции | скин и золотая рамка | приручён |

**Победа открывает клетку навсегда, даже если приручить не вышло.** Журнал
побед хранится отдельно от коллекции: приручается не всё, что побеждено,
а увиденное игрок терять не должен.

Силуэт — это `modulate` спрайта в чёрный, а не отдельная картинка: рисовать
по силуэту на каждого монстра × каждый грейд значило бы тридцать лишних
файлов, повторяющих форму основного. Гасится ТОЛЬКО спрайт, не вся клетка —
иначе чёрный силуэт на почерневшей клетке перестаёт читаться, и вместо
загадки получается пустое место.

Имя вида скрыто, пока не открыт ни один его грейд: коллекция не должна
рассказывать содержание вперёд игрока.

**Нажатие на открытую клетку показывает характеристики.** Это же и ответ
на вопрос «какой у меня защитник»: стихия, здоровье, Настрой, удар, любимый
фрукт, а у приручённого ещё уровень, опыт до следующего и вклад снаряжения.
Числа берутся у того же `MonsterInstance`, который дерётся в бою, поэтому
карточка не может разойтись с боем. По закрытой клетке нажатие не делает
ничего: молчание честнее пустой карточки.

Правила витрины живут в `CollectionGrid` отдельно от экрана: «каким показать
монстра» — это правило игры, а не рисование, и его надо уметь проверить
без поднятия сцены.

## 8. Лес (лента забега)

### 8.1 Свайп-лента

Вертикальный свайп вверх → следующая поляна. Никаких загрузок, никакой карты, никакого
выбора маршрута — только «дальше» или «домой». Соседняя поляна подгружается заранее
и частично видна снизу, как в ленте коротких видео.

**Пропустить можно только то, что уже превзошёл.** Встречу разрешено
свайпнуть мимо, если этот вид приручён **в таком же грейде или выше**.
Всё остальное — бой без вариантов: и незнакомый вид, и знакомый,
но более редкий, чем твой лучший экземпляр. Легендарный Ростик при обычном
Ростике в коллекции — обязательная встреча, а не рутина.

История правила в три шага:

1. Изначально мимо любого монстра можно было пройти. Отказались: бесплатное
   листание мимо всего опасного подменяло главное решение забега — игрок
   пролистывал до торговца, брал награды и уходил, ни разу не рискнув.
2. Потом бой стал обязательным всегда. С ростом коллекции это превращает
   ленту в обязаловку: десятый бой с давно приручённым Ростиком — рутина,
   а не риск.
3. Итог (v0.4): **обязательно всё, что для тебя ново** — новый вид или новый
   потолок грейда знакомого вида. Превзойдённое — по желанию: можно
   пропустить, можно подраться за награду (§8.1.2), и пропуск — осознанный
   отказ от неё, а не бегство от риска.

Прочие типы полян (куст, костёр, встреча) пропускаются свободно: они
не несут риска, и заставлять на них останавливаться незачем.

Кнопка «домой» доступна между полянами всегда. Выход по своей воле = **сохраняешь всю добычу**.

### 8.1.1 Свайп — не единственный способ идти дальше

Каждое действие ленты доступно **кнопкой**, а свайп её дублирует. Свайп остаётся
главным жестом на телефоне, но он не может быть единственным путём.

Причина эмпирическая. Жест зависит от порогов и от того, в каком состоянии
находится лента, и трижды подряд ломался так, что игрок оказывался заперт:
пороги считались в пикселях холста, а события приходят в координатах окна;
колесо мыши приходит тем же типом события, что и тап, с нажатием и отпусканием
в одной точке, и читалось как «повторить эту поляну». Каждый раз игра
формально работала, а пройти её было нельзя.

Отсюда правило: **у любого продвижения по ленте есть видимая кнопка**.
Кнопка не зависит ни от порогов, ни от разбора жеста, и её состояние
видно глазом — в отличие от жеста, про который нельзя понять, отключён он
или просто не сработал.

- Кнопка действия подписана по типу поляны: «Танцевать», «Собрать»,
  «Отдохнуть», «Товар». Одна подпись на все случаи так же непонятна,
  как голый жест.
- Кнопка «Дальше ↑» **гаснет** на обязательном бою (новый вид или грейд выше
  твоего экземпляра) — запрет виден сразу, а не после безрезультатного
  свайпа. На встрече с превзойдённым монстром она горит: пропуск
  разрешён (§8.1).
- Подсказка на карточке называет кнопку, а не жест.
- Клавиатура на десктопе: пробел/Enter — действие, стрелка вверх и колесо — переход.
  Это нужно не игроку на телефоне, а тому, кто проверяет игру.

### 8.1.2 Карточка боя: что на кону

Раз превзойдённого монстра можно пролистать, карточка обязана показывать,
**что игрок теряет, пролистывая**. Всё видно до боя, без слов — иконками:

| Что на кону | Как показано |
|---|---|
| Грейд экземпляра | цвет рамки карточки (§6.3), легендарный переливается |
| Любимый фрукт | иконка над монстром (§6.2) — уже было |
| Дружба этого грейда | полоска с текущим прогрессом и «+10» за победу; порог — свой у грейда |
| **«Можно подружиться!»** | крупная пометка, если дружба уже достигла порога ЭТОГО грейда — победа приручит экземпляр |
| Сундук за победу | иконка сундука в цвете самого вероятного тира (шансы по грейду — [drop_tables.json](data/drop_tables.json)) |
| Опыт и серебро | маленькие иконки с числами |

Иерархия подачи: «можно подружиться» затмевает всё; затем грейд;
остальное — мелким рядом внизу карточки. Карточка продаёт бой,
как витрина, — решение «остановиться или дальше» должно приниматься
за секунду по одному взгляду.

Пропуск ничего не двигает: дружба и опыт против вида растут только
из боя. Пролистал — значит отказался, и это честная цена решения.

**После боя поляна пуста.** Витрина существует, только пока на кону
что-то есть. Когда бой окончен — победой или бегством монстра, — карточка
теряет всё: спрайт, шкалу дружбы, строку про сундук и серебро; остаётся
«Поляна опустела», итог боя и «Дальше». Возвращать её в прежнем виде
нельзя: монстра здесь уже нет, а витрина продолжает продавать бой,
которого не будет, — игрок читает это как «сюда можно ещё раз».
Сторож — `tests/test_glade_once.gd`.

| Тип | Доля | Содержание |
|---|---|---|
| Бой | 65% | Дэнс-баттл. Основа ленты |
| Дикий куст | 12% | Мини-игра сбора в такт → семена нового вида |
| Костёр | 8% | Восстановление здоровья, смена гуардиана из коллекции |
| Встреча | 15% | Случайная сцена: торговец, куст с лутом, бабка — §8.2.1 |

Доли — настройка в [drop_tables.json](data/drop_tables.json).

### 8.1.3 Экран победы: опыт, потом призы

Порядок здесь не украшение. Сперва игрок видит, что его существо стало
сильнее, и только потом — что нашлось в сундуке: рост защитника легко
теряется среди строк добычи, а он и есть долгая прогрессия (§6.5).

1. **Опыт полоской.** Ползёт, а не прыгает: рост, случившийся мгновенно,
   читается как «уже было так». При переходе уровня полоска добегает
   до края, обнуляется и идёт дальше — ровно так, как это и произошло.
2. **Что выросло.** Взяли уровень — показываем прибавку статов числами
   «было → стало». Без этого «уровень 3» остаётся числом, за которым
   не видно ни здоровья, ни удара.
3. **Призы по одному**, каждый с картинкой. Строка «Сундук: Кожаный пояс»
   требует чтения, пояс на экране узнаётся сразу.
4. **Ничего не выпало — ничего и не пишем.** Пустая строка «сундук: нет»
   занимает место и сообщает только о неудаче.

**Свайп и кнопка появляются в КОНЦЕ показа.** Иначе половину пролистывают,
не заметив, и весь экран теряет смысл.

Сундук при этом падает НЕ всегда (§8.1.2): пока вещь давала каждая победа,
снаряжение перестало быть событием — его набиралось больше, чем игрок
успевал надеть, а торговец стал не нужен.

### 8.2.1 Встречи

Встреча — поляна со случайной сценой без риска. Виды и доли (конфиг):

| Встреча | Доля | Что происходит |
|---|---|---|
| **Бродячий торговец** | 45% | Всегда 3 товара за серебро: снаряжение, семена, зелья. Цены — [merchant.json](data/merchant.json) |
| **Куст с лутом** | 35% | Потряси в такт: случайный лут обычного грейда (зелье, семя, горсть серебра), с небольшим шансом — сундук со снаряжением, как за победу |
| **Бабка** | 20% | Просит случайную сумму серебра — **никогда больше, чем есть у игрока**. Дал — получишь подарок-сюрприз; отказал — ничего не случится, без наказания |
| Загадка | позже | Ритм-мини-игра; до реализации её доля уходит торговцу |

Бабка — единственная сцена, где игра просит отдать своё. Правило «не больше,
чем есть» жёсткое: предложение, которое нельзя принять, — это издёвка,
а не выбор. Отказ ничего не стоит — щедрость награждается, жадность
не наказывается.

### 8.2.2 Лавка в усадьбе

Второй прилавок стоит во дворе (§7.4): **фиксированный набор слотов, состав
обновляется раз в 10 минут**. Здесь всегда есть базовые семена, плюс пара
зелий и пара вещей по ротации. Это место, где запасаются ПЕРЕД выходом
в лес, — в самом забеге торговец встречается случайно и товар не выбирает.

Ротация — не FOMO-таймер (§2.4): ничего не исчезает навсегда, базовые семена
в продаже постоянно, опоздать невозможно. Витрина считается от часов
(`floor(unix_time / 600)`), а не разыгрывается: перезаход в игру не должен
перебрасывать товар, иначе появляется смысл «перезаходить до нужного».
Ассортимент идёт по кругу, а не случайной выборкой — за несколько ротаций
игрок увидит всё, а не будет ждать милости рандома.

**Наряды за золото — отдельный экран.** Из лавки в него ведёт отдельная
кнопка, и две валюты не встречаются на одном прилавке: разделение контуров
(§12) должно быть видно даже в раскладке, а не только в коде.
Состав и цены — [merchant.json](data/merchant.json).

### 8.2.3 Костёр: лечение стоит угощения

Костёр сам по себе **не лечит**. У него едят фрукты — те самые, которыми
иначе угощают монстров ради дружбы. Это единственное настоящее решение
внутри забега: идти дальше побитым и сохранить угощение или подлечиться
и отложить нового друга.

Зелья упразднены именно ради этого. Пока лечение лежало в сумке отдельным
предметом, оно ничего не стоило — выпил и пошёл; а даровой костёр не стоил
даже нажатия.

Съеденный плод даёт и **баф до конца забега** — не на один бой: съеденное
должно ощущаться вложением. Бафы мелкие и подкручивают бой, а не выигрывают
его: решает по-прежнему попадание в такт (§2.1).

| Тир | Лечит | Баф |
|---|---|---|
| обычный | 12 | — |
| необычный | 22 | защита +8% |
| редкий | 36 | удар +1.2 |
| эпический | 55 | окно +15% |

У каждого бафа свой потолок за забег, иначе достаточно съесть десяток
яблок, и окно попадания перестаёт что-либо значить. Все числа —
в `data/fruits.json`, в коде их нет ни одного.

### 8.3 Кривая сложности

Глубина забега `d` делает ровно одно: **сдвигает веса грейдов к редким**
(таблица и формула сдвига — [drop_tables.json](data/drop_tables.json)).
Настрой, плотность нот и частота щитов от глубины НЕ зависят: вся сложность
боя — свойство грейда экземпляра, то есть более быстрый ремикс (§10.1.1)
и ×Статы (§6.3).

Так уровень сложности всегда виден до боя — по цвету рамки монстра,
а не по невидимому счётчику полян. Ребёнок понимает «золотой — страшно»
без чисел.

Награды при этом растут с глубиной: `base × (1 + 0.15 × d)` — решение
«ещё одна поляна» обязано оставаться ставкой.

Забег бесконечен математически, но практический потолок — 25–40 полян.

### 8.4 Смерть (мягкая)

При обнулении здоровья:

| Сохраняется | Теряется |
|---|---|
| Все приручённые гуардианы | 50% собранных за забег фруктов |
| Вся дружба, накопленная в забеге | 50% собранного серебра |
| Найденное снаряжение | — |
| Найденные семена | — |

Экран поражения формулируется позитивно: не «ты проиграл», а «гуардиан устал»,
с показом того, что было добыто и насколько продвинулась дружба.

## 9. Снаряжение

### 9.1 Гуардиан — 3 слота (все статы здесь)

| Слот | Влияет на |
|---|---|
| **Пояс** | Ширина окна тайминга (прощение промахов) |
| **Плащ** | Сила атаки |
| **Головной убор** | Максимальное здоровье, крепость щита |

**Надетое видно на гуардиане в бою.** Без этого собирать снаряжение незачем:
предмет, который нигде не отображается, ничем не отличается от строчки в таблице.

Снаряжение — главный способ бить сильнее, потому что весь урон боя сосредоточен
в атакующих нотах, а их сила зависит от плаща и от опыта против вида (§6.4).

### 9.1.1 Откуда берётся снаряжение

| Источник | Что даёт |
|---|---|
| **Победа над монстром** | Сундук со снаряжением, состав случайный |
| Бродячий торговец (лес и ферма, §8.2.1–8.2.2) | Прямая покупка за серебро |
| Куст с лутом, бабка (§8.2.1) | Изредка — случайный предмет |

Сундук за победу — это НЕ платный лутбокс: он не покупается и не связан
с реальными деньгами, поэтому регуляторные правила лутбоксов ([SHOP.md](SHOP.md)) к нему не относятся.
Но правило «дубль не пропадает впустую» действует и здесь.

### 9.2 Косметика — ровно ноль влияния на геймплей

**Изначально здесь были микробафы героя (+2–5%) с рассуждением, что они слишком
малы, чтобы считаться pay-to-win. При реализации это правило ужесточено.**

Причина: +5% к скорости роста фермы — это преимущество, каким бы маленьким оно
ни было. В игре, ориентированной в том числе на детей, продавать преимущество
за реальные деньги нельзя даже на пять процентов. Граница «маленький бонус можно»
не проводится честно ни в дизайне, ни в разговоре с регулятором.

Итоговое разделение:

| Что | Валюта | Влияние на геймплей |
|---|---|---|
| **Снаряжение гуардиана** (`GearData`) | Серебро (игровое) | Да — окна, урон, здоровье |
| **Косметика** (`CosmeticData`) | Золото (за деньги) | **Нет, вообще** |

Косметика: наряды, головные уборы, инструменты, виды грядок, эффекты нот,
танцевальные движения.

Правило закреплено **структурой данных, а не соглашением**: у `CosmeticData`
физически нет полей, которыми можно дать преимущество. Pay-to-win невозможен
не потому, что о нём договорились, а потому что его негде записать.
Проверяется тестом, перебирающим запрещённые имена полей.

## 10. Музыка и генерация чартов

Музыка — не оформление, а игровая механика. Раздел описывает продакшен-пайплайн.

### 10.1 Требования к треку

- Длина: 20–35 секунд, зацикливаемый
- Стабильный BPM (без rubato) — обязательное условие для чарта
- **Цепляющая мелодия** — главный критерий отбора, важнее качества сведения
- Чёткая ритм-секция: слышимый kick/snare на сетке
- Жанровая принадлежность из списка раздела 5

### 10.1.1 Темп по грейду — сложность это ремикс

Чем реже монстр, тем быстрее он ведёт танец. Это **не ускорение записи** —
питч поплывёт, и трек зазвучит игрушечно, — а отдельный ремикс того же мотива
в более высоком темпе. Три темповые ступени на каждую стихию:

| Ступень | Грейды | Характер |
|---|---|---|
| Спокойный | Обычный, Необычный | базовый темп мотива |
| Быстрый | Редкий, Уникальный | BPM +15–20%, плотнее ритм-секция |
| Бешеный | Эпический, Легендарный | BPM +30–40%, синкопы, больше особых нот |

Это и есть «3 уровня сложности» авточарта из §10.2: сложность привязана
к грейду экземпляра, а не к глубине забега (§8.3). У каждой ступени свой чарт,
размеченный под её темп, — плотность нот не подкручивается на лету.

### 10.1.2 Музыка вне боя

Всё, что звучит не под чарт, устроено иначе и живёт отдельно от `Conductor`:
под эту музыку не играют, её слушают. Отсюда три формы и разные требования.

**Джинглы** — событие в две-четыре секунды: вход в игру, победа, поражение.
Звучат поверх фона на шине `SFX` и никогда не зацикливаются. Заставочный
джингл цитирует главный мотив матрицы: игра обязана начинаться той же
музыкой, которой продолжается.

**Петли экранов** — своя на каждом месте усадьбы: двор, огород, дом
защитников, амбар, лавка, магазин нарядов, угощение, лес. Требование
именно «своя, а не какая-нибудь»: по музыке должно быть слышно, где ты,
раньше, чем прочитаешь заголовок. Петли разреженные — в лавке стоят
подолгу, и плотный рисунок через десять минут начинает раздражать.
Смена экрана даёт перекрёстное затухание, обрыв на полуноте читается
как сбой. Возврат на покинутый экран музыку **не** перезапускает.

**Мелодии полян** — не меньше пяти на каждый тип (бой, дикий куст, костёр,
встреча); у боя их десять, потому что боевых полян в ленте больше всех
и разнообразие там нужнее. Пять, а не одна: лента по замыслу бесконечна,
и на десятом кусте единственный мотив превратился бы в метроном.

Вариант выбирается **мешком, а не броском кубика**. Мешок перемешивается
и раздаётся до дна, и только потом набирается заново; при пересборке
последняя сыгранная мелодия отодвигается от начала. Случайный выбор
на каждом показе даёт повторы подряд заметно чаще, чем игрок готов
списать на совпадение, — «опять эта же» ощущается поломкой. Тот же приём
и по той же причине применён к фонам леса (§11.1.0).

Бой глушит фоновую музыку целиком: чарт и петля разом — каша, под которую
ещё и попадать в такт. После боя лес возвращается.

Всё перечисленное синтезируется из данных (`beatroot_chartgen/cue.py`)
и раскладывается по `music/cue`, `music/ui`, `music/glade`. Проигрыванием
ведает автозагрузчик `Jukebox`; сторож — `tests/test_music.tscn`, который
проверяет, что у каждого экрана мелодия своя и что пул поляны не похудел.

### 10.2 Пайплайн

```
  [1] Генерация      MCP → генератор музыки, батчами по 20–50 треков
        │            промпт-шаблон под жанр + целевой BPM
        ▼
  [2] Ревью          ЖЁСТКИЙ ручной отбор. Ожидаемый пропуск: 1 из 10–15.
        │            Критерий №1 — запоминается ли мелодия после одного прослушивания.
        ▼
  [3] Ремикс         Прошедший мотив переаранжируется в 4 других жанра
        │            и в 3 темповые ступени (§10.1.1). Один мотив = до 15 треков.
        ▼
  [4] Анализ         BPM-детект, beat grid, onset detection, разметка секций.
        │            Инструмент: Python + librosa/aubio.
        ▼
  [5] Авточарт       Генерация нот по онсетам, по чарту на темповую ступень.
        │            Правила: щиты только на сильные доли, скиллы по кулдауну.
        ▼
  [6] Ручная правка  CHART FORGE — редактор чартов (см. 10.3)
        │
        ▼
  [7] Экспорт        res://music/<id>.ogg + res://charts/<id>.tres
```

### 10.3 Chart Forge — отдельный инструмент

Автоматика ставит ноты по онсетам, но **играбельность требует руки**. Нужен редактор.

**Ключевое решение: писать редактор как инструмент внутри Godot (EditorPlugin или
отдельная сцена проекта), а не как веб-приложение.**

Обоснование: редактор обязан использовать **тот же аудиодвижок и тот же код Conductor**,
что и игра. Чарт, идеально выровненный в браузере, поедет в Godot из-за другой модели
буферизации и латентности. WYSIWYG здесь не удобство, а требование корректности.

Функции Chart Forge:

- Загрузка трека, waveform + сетка тактов, привязка BPM и offset
- Импорт автосгенерированного чарта из Python-анализатора (JSON)
- Расстановка/сдвиг/удаление нот с привязкой к долям и сабдивизиям
- Разметка танцевального паттерна монстра (когда он замахивается → куда встают щиты)
- Мгновенный playtest в реальном игровом бою, без перезапуска
- Автопроверка: плотность нот в окне, нет ли двух щитов подряд, играбельность для 7-летнего
- Экспорт в `ChartResource` (.tres)

**Редактор обязан знать каждый тип ноты.** Атакующие ноты добавили в игру,
а таблицы кистей и цветов в Chart Forge не тронули — и редактор падал
на отрисовке любого настоящего чарта. Ошибка была видна в логе, но не роняла
ни один тест: таблицы никто не сверял с перечислением типов. Теперь сверяет
`tests/test_validator.tscn`, и добавление типа без кисти в редакторе —
это провал тестов, а не сюрприз при открытии.

Цвет ноты в редакторе — **тот же**, что в бою. Редактор показывает ноту так,
как её увидит игрок, иначе разметка ведётся вслепую.

### 10.4 Технический тайминг (критично)

Ритм-игра живёт или умирает на этом. Правила:

- **Единственный источник времени — позиция аудиопотока**, не `delta` из `_process`
- Формула:
  `time = player.get_playback_position() + AudioServer.get_time_since_last_mix() - AudioServer.get_output_latency()`
- Ноты позиционируются по музыкальному времени (доли), не по секундам и не по пикселям
- **Обязательна калибровка задержки** при первом запуске: игрок тапает под метроном 8 раз,
  игра вычисляет персональное смещение аудио и ввода. На Android разброс латентности огромен —
  без калибровки игра будет казаться сломанной на половине устройств
- Аудио: `.ogg` для музыки, `.wav` для UI-звуков (без задержки декодирования)

## 11. Арт и ассеты

### 11.1 Направление стиля: HD-пиксель

**Референс: Graveyard Keeper.** Высокая плотность пикселя, живописная растушёвка вместо
плоских заливок, приглушённая земляная палитра, плотная детализация окружения.
Референс используется **только как указатель направления** — ни один его ассет
не попадает в проект.

Что берём:

- **Плотность пикселя.** Не ретро 32×32, а «пиксель высокого разрешения»: детализация
  ближе к живописи, ограниченная палитра и видимая пиксельная сетка как стилевой приём
- **Палитра.** Тёплые земляные тона: охра, терракота, оливковый, приглушённая зелень
- **Растушёвка.** Мягкие переходы и объём, а не celshade с жёстким контуром
- **Фактура среды.** Трава, доски, камень с ощутимой текстурой — это создаёт уют

Что меняем под нашу игру — обязательно:

1. **Масштаб персонажей.** В референсе персонажи мелкие, камера далеко. У нас монстр
   **танцует крупным планом** в верхней трети телефона. Персонажи должны быть в разы
   крупнее и выразительнее относительно кадра — иначе на маленьком экране не читается мимика
2. **Плотность деталей вниз.** Референс — ландшафтный PC-экран. Наш портретный телефон
   с той же детализацией превратится в кашу. Фон боя — упрощённый, силуэтный
3. **Настроение.** Референс мрачноват. Наша палитра сдвигается в сторону света и тепла:
   те же земляные тона, но выше яркость и больше зелени. Игра для детей должна быть солнечной

### 11.1.0 Фоны леса: ротация и исключения

Лес в ленте — двадцать разных мест, а не одно. Фон меняется на каждой поляне,
и порядок задан мешком: все двадцать показываются по разу в перемешанном
порядке, и лишь потом набираются заново. Не бросок кубика — чистый случайный
выбор из двадцати даёт повтор подряд примерно каждый двадцатый раз, а повтор
подряд игрок читает не как совпадение, а как «фон не сменился». На стыке
мешков повтор запрещён отдельно.

Два типа поляны из ротации исключены: **костёр** и **встреча**. У них фон сам
является содержанием — на нём горит огонь и стоит навес торговца, и подменить
его безымянным лесом значило бы убрать со сцены то, ради чего игрок остановился.
У боя и дикого куста фон — просто место, а что там происходит, говорят
заголовок, спрайт на карточке и мелодия (§10.1.2).

Тот же лес и в первой встрече интро, но выбранный **один раз**: при поражении
показывается та же фраза и тот же монстр, и менять под ними декорацию значило бы
сказать, что игрок ушёл в другое место.

Ротацией ведает `ForestScenery`; сторож — `tests/test_scenery.tscn`.

### 11.1.1 Правило контраста (критично для ритм-игры)

Приглушённая земляная палитра — **низкоконтрастная**, а ритм-игра требует, чтобы нота
читалась мгновенно. Это прямой конфликт стиля и механики, и решается он жёстким правилом:

> **Палитра игровых элементов зарезервирована.** Ноты, шкалы, индикаторы замаха и щита
> используют насыщенные яркие цвета, которые **не встречаются в окружении вообще**.
> Ни один куст, ни одна доска, ни один монстр не имеет права быть такого цвета.

Дополнительно: при входе в бой фон **притемняется и обесцвечивается** на 25–35%.
Мир остаётся узнаваемым, но перестаёт спорить с нотами за внимание.

Проверка стиля: скриншот боя, уменьшенный до 30% и размытый, должен всё ещё позволять
безошибочно найти все ноты. Если не позволяет — палитра нарушена.

### 11.1.2 Почему HD-пиксель выполним генерацией

Ранее я рекомендовал мультяшный вектор именно из-за трудностей генерации пикселя.
HD-пиксель это возражение снимает:

- Проблема диффузионных моделей — **низкое** разрешение: они не умеют попадать в сетку
  16×16 и выдают грязь. HD-пиксель по сути детализированная живопись с ограниченной
  палитрой — модели делают это уверенно
- Пиксельность добивается постобработкой: даунскейл + квантование палитры,
  а не выпрашивается у модели промптом
- Единая палитра проекта, применённая при квантовании, **сама по себе даёт консистентность
  стиля** — это решает главную проблему генеративного пайплайна дешевле, чем LoRA

Цена решения: ручная чистка каждого ассета после квантования обязательна.
Заложить в оценку ~30–40 минут доводки на монстра сверх генерации.

### 11.2 Анимация танца — ключевое техническое решение

Монстры должны танцевать. Покадровая анимация десятков монстров нереальна для одного
человека, а генерация консистентных спрайт-листов через ComfyUI не работает.

**Решение: ComfyUI генерирует статичный персонажа → разрезается на части →
собирается скелетный риг в Godot (Skeleton2D + cutout) → танцы делаются как
переиспользуемые анимации на риге.**

Следствия:
- 4–5 **шаблонов силуэта** (двуногий, четвероногий, летающий, шарообразный, змеевидный)
- Все монстры одного силуэта делят **общую библиотеку танцев**
- Новый монстр = генерация арта + разрезка + привязка к рингу ≈ час работы, а не день
- Танцевальные анимации создаются один раз и работают на всей коллекции

Это единственный способ получить сотню танцующих монстров силами маленькой команды.

### 11.2.1 Конфликт: пиксель-арт не терпит поворота

Скелетная анимация вращает спрайты. Повёрнутый на произвольный угол пиксель-арт
разрушает сетку: края «кипят», пиксели становятся разного размера. Вблизи это выглядит
как техническая ошибка, и никакой фильтрацией не лечится.

**Решение: рендерим ригом, но запекаем в спрайт-лист.**

```
  риг в высоком разрешении  →  проигрываем танец  →  рендер кадров
        │                                                  │
        │                                                  ▼
        │                                     даунскейл + квантование палитры
        │                                                  │
        └──── правится один раз ────────────────────────► спрайт-лист в игру
```

Пикселизация применяется **после** поворота, ко всему кадру целиком — сетка получается
единой и чистой. В игре крутится уже не риг, а готовые кадры.

Что это даёт:
- Сохраняется главный выигрыш: одна библиотека танцев на все монстры силуэта
- Пиксель остаётся честным, без «кипения» краёв
- Рантайм дешевеет: `AnimatedSprite2D` вместо иерархии `Skeleton2D` на слабых телефонах

Цена: запекание надо автоматизировать. Это **отдельный инструмент** — скрипт в Godot,
прогоняющий риг по всем анимациям и сохраняющий листы. Планировать в Фазе 4
вместе с Chart Forge. До Фазы 4 хватит ручных спрайтов на 3–5 тестовых монстров.

Частота кадров танца: 12 fps. Ниже — рвано, выше — не читается на пиксель-арте
и раздувает атлас.

### 11.3 ComfyUI пайплайн (RTX 4090)

Ключевой принцип: **модель рисует живопись, пиксель делает постобработка.**
Не пытаться выпросить пиксель-арт промптом — это главная ошибка в таких пайплайнах.

```
  [1] Генерация     SDXL/Illustrious, промпт = живописный ассет в высоком разрешении.
        │           Фиксированный шаблон промпта, вариативность только в описании существа.
        ▼
  [2] Фон           Автоудаление фона, вывод с альфа-каналом.
        ▼
  [3] Даунскейл     До целевого разрешения ассета, nearest neighbour.
        ▼
  [4] Квантование   Приведение к ЕДИНОЙ палитре проекта (~48–64 цвета).
        │           Это шаг, который делает разрозненные генерации одной игрой.
        ▼
  [5] Ручная чистка Края, читаемость силуэта, детали лица. ~30–40 мин на монстра.
        ▼
  [6] Разрезка      Части тела → риг (см. 11.2) → запекание в спрайт-лист.
```

- **Палитра проекта — единый файл**, применяется на шаге 4 ко всему. Она важнее LoRA:
  консистентность цвета читается глазом сильнее, чем консистентность мазка
- LoRA на стиль обучаем **после** того, как накопится 50+ вручную доведённых ассетов —
  тогда есть на чём учить, и она закрепит уже найденный стиль, а не выдуманный
- Что генерируется: монстры, фрукты, семена, снаряжение, фоны полян, косметика
- Что рисуется вручную **всегда**: UI, ноты, индикаторы щита и замаха.
  Это элементы, от читаемости которых зависит честность боя — их нельзя отдавать генерации

### 11.4 Тема интерфейса

Интерфейс рисуется **одной темой** — `art/ui/beatroot_theme.tres`, подключённой
проектом целиком. До неё каждый экран задавал кегли и цвета сам, а всё
остальное доставалось от темы Godot по умолчанию: плоские серые прямоугольники
без скруглений и глубины. Игра выглядела не игрой, а системным приложением,
и никакая красота фонов этого не перебивала — взгляд цепляется за кнопку.

Тема — **ресурс, а не код**. Это то же правило, что и для сцен (§13.2.1):
радиус, цвет и отступ должно быть видно в инспекторе, иначе подкрутить их
нельзя без программиста.

Что тема задаёт и почему именно так:

- **Скругление 20–28 и тёплое дерево** из ветки `wood`/`warm` палитры.
  Насыщенные цвета не берутся принципиально: они зарезервированы под ноты
  и шкалы боя (§11.1.1), и кнопка такого же цвета спорила бы с нотой
  за внимание.
- **Нижняя грань кнопки толще верхней** — 7 против 3. Кнопка читается
  объёмной без единой картинки, а при нажатии грани меняются местами,
  и нажатие видно.
- **Обводка у всех подписей.** Текст лежит на пёстром лесу и на дворе;
  без обводки буквы теряются в траве. Это читаемость, а не украшение.
- **Кнопка ростом не ниже 110 пикселей холста** — примерно 10 мм на телефоне.
  По меньшей детский палец промахивается, а промах в меню ребёнок читает
  как «игра сломалась».
- **Картинка в строке списка.** Семилетний узнаёт вещь по виду быстрее,
  чем прочитает название, поэтому в лавке, амбаре, магазине и на грядках
  у каждой строки есть иконка (`UIUtil.decorate_row`).
- **Монета вместо слова в кошельке.** Серебро и золото показаны иконками
  `art/currency/`, а не подписями «Серебро»/«Золото»: монета читается
  быстрее слова и не зависит от языка. Строка кошелька собирается
  в одном месте — `UIUtil.purse_bbcode` — потому что показана она на пяти
  экранах, и пока каждый склеивал её сам, они разъезжались и по формату,
  и по составу. Кошельки поэтому `RichTextLabel`, а не `Label`: иконка
  в строке — это `[img]`, и `Label` его не умеет. Контуры валют
  разделимы (§12): у торговца показано только серебро, в магазине
  нарядов — только золото.

Сторожа два: `tests/test_readability.tscn` меряет, помещается ли текст
в отведённое место и не мельче ли кнопка порога, а `tools/shotgun/`
снимает все экраны в PNG — вёрстку всё равно принимают глазами,
и снимок дешевле запуска игры.

### 11.5 Лицензионное ограничение

Игра коммерческая (с магазином). Из этого следует:

- Модели и LoRA — только с лицензией, разрешающей коммерческое использование
- Никаких LoRA, обученных на конкретных художниках или на артах существующих франшиз
- Сгенерированное используется как **черновик**, доводится вручную — это и защищает
  авторские права на результат, и повышает качество
- Все музыкальные генераторы — проверить лицензию на коммерческий выход до начала продакшена
- Ассеты из внешних источников — только CC0 или купленные, с фиксацией происхождения в `ASSETS.md`

## 13. Техническая архитектура (Godot 4.6)

### 13.1 Autoload-синглтоны

| Синглтон | Ответственность |
|---|---|
| `Conductor` | Единственный источник музыкального времени. Такты, доли, сигналы `beat`, `bar` |
| `GameState` | Коллекция экземпляров, дружба по грейдам, инвентарь, снаряжение, пол героя |
| `FarmState` | Грядки, рост, семена |
| `ShopState` | Золото, наряды, сундуки, дневной лимит |
| `OnboardingState` | Пройдено ли обучение и куда пускать при запуске |
| `SaveManager` | Сохранение в `user://`, автосейв между полянами, версия схемы |
| `AudioBus` | Шины, громкость, калибровка задержки |
| `Jukebox` | Музыка вне боя: петли экранов, мелодии полян, джинглы (§10.1.2) |
| `RunManager` | Состояние текущего забега: глубина, здоровье, щит, добыча |

Автозагрузчиков ровно столько, сколько нужно СОСТОЯНИЮ, живущему между
сценами. Всё остальное — статические классы без узла: `Registry` (реестр
`.tres`), `Balance` (балансовые таблицы), `ChartSelect` (подбор чарта),
`MerchantStock` (витрина), `NoteRules` (дорожки нот), `ForestScenery`
(ротация фонов), `MonsterInstance` (экземпляр монстра).

Разница не стилистическая: статику видно из headless-теста без поднятия
дерева, и именно поэтому таблицы и правила живут в ней, а не в автозагрузке.

Состав таблицы сторожит `tests/test_gdd.tscn` — документ, разошедшийся
с `project.godot`, хуже отсутствующего.

### 13.2.1 Сцены собираются в редакторе, а не кодом

**Правило: всё, что видно на экране, лежит в `.tscn` и правится в инспекторе.
Код отвечает за поведение, а не за расстановку.**

Первая версия строила интерфейс целиком в `_build_ui()`: узлы создавались
через `Button.new()`, координаты прописывались числами. Это работало, но цена
решения перевесила удобство генерации:

- в редакторе Godot сцены выглядели пустыми — увидеть экран можно было
  только запустив игру
- правка отступа требовала программиста и перезапуска
- художник и дизайнер не могли тронуть ничего вообще

Для игры, где раскладка будет меняться десятки раз под живые прогоны,
это неприемлемо. Сцены переводятся в `.tscn` с узлами и якорями;
скрипты получают ссылки через `@onready` и занимаются только логикой.

Исключения, где генерация кодом остаётся оправданной:

- **список переменной длины** (грядки, карточки монстров, товары) — сцена
  описывает ОДИН элемент, код размножает его
- **отрисовка нот** через `_draw()` — их десятки в секунду, и узлы тут дороже

**Сделано.** Шесть экранов переведены: ферма, лента забега, друзья, лавка,
сумка, бой. Раскладку собрал тот же код, что строил её раньше
(`tools/scene_bake`), — переписывать сотни координат руками значило бы
сверять их глазами. Скрипты держат `@onready`-ссылки по именам узлов;
подключение сигналов вернулось в `_ready`, потому что лямбды
в `PackedScene` не сохраняются, да и это поведение, а не раскладка.

Правило на будущее: **узел в сцене задаёт ГДЕ, скрипт — ЧТО**. Крестики
на побеждённом монстре и линия серии рисуются в `_draw()`, но сами узлы
лежат в `.tscn` и двигаются в инспекторе.

### 13.3 Принципы

- **Данные — в `Resource`**, не в коде. Монстр, фрукт, снаряжение, чарт — всё `.tres`,
  правится в инспекторе без программиста. Критично для баланса
- **Пул объектов для нот.** На высокой сложности до 8 нот/сек; создавать и удалять узлы
  в бою — гарантированный джиттер на слабых телефонах
- **Портрет, `canvas_items` stretch, базовое разрешение 1080×1920**
- **Mobile renderer**, уже включён в `project.godot`
- **Бой не зависит от частоты кадров.** Логика оценки — по музыкальному времени;
  просадка кадров не должна ломать тайминг
- Сейв: JSON в `user://`, версионирование схемы с первого дня

### 13.4 Целевая производительность

60 FPS на устройстве уровня Snapdragon 6-й серии. Ритм-игра при 30 FPS ощущается
неотзывчивой — это не оптимизация «потом», а требование к первому прототипу.

### Фаза 0 — Вертикальный срез тайминга (важнейшая)

Цель: доказать, что ритм-ядро работает на реальном телефоне.

- Один трек, один чарт, вручную размеченный
- Один бой: только ноты-биты, оценка, комбо
- Экран калибровки задержки
- **Тест на физическом Android-устройстве**

Критерий выхода: играется приятно на телефоне, тайминг не плывёт за 30 секунд.
Если этого нет — остальное не имеет смысла.

### Фаза 1 — Петля забега

Свайп-лента, 3 монстра, щиты, шкала дружбы, приручение, мягкая смерть, возврат домой.

Грядки, реалтайм-рост, танец растению, любимые фрукты, дикие семена в лесу.

## 15. Открытые вопросы

Требуют решения по мере разработки, зафиксированы чтобы не потерялись:

1. **Смена гуардиана в забеге.** Сейчас — только у костра. Проверить: не слишком ли редко.
2. **Потолок глубины.** Нужен ли мягкий стоп на ~40 поляне, или пусть будет честная бесконечность.
3. **Сколько треков нужно на старте.** Оценка: 15–20 уникальных мотивов × 5 жанровых
   ремиксов = 75–100 боевых треков. Проверить на плейтесте, за сколько боёв наступает
   усталость от повтора.
4. **Оффлайн-рост фермы и читы с системным временем.** Нужна защита от перевода часов.
5. **Онбординг без текста.** Механика сделана: пульсирующее кольцо сжимается
   к линии удара за одну долю и показывает «когда», призрачный палец
   показывает «как», Настрой монстра занижен так, чтобы первый опыт заведомо
   кончился победой. Урок идёт на настоящем бою — всё, чему он учит, остаётся
   правдой в игре.

   **Переработка v0.4 (не реализовано).** Запуск идёт цепочкой
   сплеш → выбор персонажа (мальчик или девочка, без текста) → встреча в лесу
   → бой. На фоне леса во весь экран появляется фраза «Однажды гуляя в лесу
   вы встретили *имя*»; монстр случайный, **всегда обычного грейда**.
   Первый бой игрок танцует ОДИН, без гуардиана — герой со стартовыми статами.
   Проигрыш не наказывается и не пропускается: та же фраза, тот же монстр,
   бой заново — выйти из интро можно только победой. Победа даёт фразу
   «Теперь *имя* ваш защитник», монстр присоединяется сразу, минуя шкалу
   дружбы (единственное исключение из §6.1), и становится первым гуардианом.
   Та же фраза показывается и при обычном приручении в лесу — момент должен
   читаться одинаково. Стартового монстра «из коробки» больше нет.

   **Правило «без текста» при этом не отменяется, а уточняется:** текстом
   становится только повествовательная рамка — две фразы на входе. Всё,
   что учит механике, по-прежнему показывается кольцом, пальцем и цветом,
   и ребёнок, не читающий бегло, ничего не теряет: на обеих фразах видно
   монстра, а единственное действие — «дальше». Обе строки идут
   через локализацию (§15.6), а не литералами по коду.
6. **Локализация.** Русский и английский на старте; дизайн UI должен быть иконочным,
   чтобы это ничего не стоило.
7. **Название.** BEATROOT — рабочее. Проверить занятость домена, товарного знака
   и наличие тёзок в сторах до вложений в брендинг.
8. ~~**Рост гуардиана после приручения.**~~ **Решено (v0.4):** уровни
   экземпляра + снаряжение, §6.5. Эволюции не будет.
9. ~~**Грейд — свойство вида или экземпляра?**~~ **Решено и сделано (v0.4):**
   экземпляра, §6.3. Коллекция хранит экземпляры «вид + грейд + уровень»,
   сейв поднят до версии 2, несовместимые старые сейвы отбрасываются.
10. ~~**Скилл-нота не спроектирована.**~~ **Решено (v0.4):** особая нота,
    спецдвижение по стихии гуардиана, промах бьёт на 6, §4.2.4.
11. **Торговец на ферме не сделан.** В лесу встреча с 3 товарами за серебро
    работает (§8.2.1), точка на ферме с ротацией раз в 10 минут (§8.2.2) —
    нет. Пока зелья и снаряжение покупаются только в забеге, и запастись
    перед выходом негде. Цены — [merchant.json](data/merchant.json).
12. ~~**Поляна-событие пустая.**~~ **Решено (v0.4):** тип «Встреча»
    с торговцем, кустом с лутом и бабкой, §8.2.1. Загадка — позже.
13. **Награды бабки.** Таблица подарков задана первым приближением
    ([drop_tables.json](data/drop_tables.json)); проверить на плейтесте,
    что щедрость ощущается вознаграждённой, а не обманутой.
14. **Загадка-мини-игра** для встреч (§8.2.1) — спроектировать.
15. **Баланс зелий.** Два вида на старте (items.json); проверить, не делает
    ли дешёвое зелье костёр бессмысленным.
16. **Опыт за победу — цифры.** База, бонус за грейд противника и S-ранг
    заданы первым приближением в [progression.json](data/progression.json);
    подогнать по плейтесту так, чтобы 10-й уровень был делом недель, а не дней.
17. **Две кнопки не проверены на устройстве.** Автотесты подтверждают только
    маршрутизацию: щит не берётся обычной кнопкой, зелье принимает обе.
    Ощущение — попадает ли палец, не мешает ли разделитель, не двоится ли
    касание из-за эмуляции мыши — headless не проверяется в принципе.
18. **Угощение живёт в коллекции, а не на ферме.** GDD §6.5 говорит
    «кормление на ферме», сделано на карточке друга: там уже есть экземпляры
    и панель. Решить, где этому место, когда ферма обзаведётся своим
    экраном друзей.
19. **Настрой вида и его чарт связаны вручную.** Число атакующих нот зависит
    от жанра (у латины их вчетверо меньше, чем у фолка), а Настрой прописан
    в `.tres` отдельно — и разъезжаются они молча, до первого живого прогона.
    Стоит считать Настрой от чарта (например, «столько-то удавшихся атак
    на победу») или хотя бы сверять их тестом при генерации новой музыки.
20. **Промахи почти обнуляют прокачку.** Рваная серия отменяет атаку целиком,
    поэтому при точности ниже 80% ни уровень, ни снаряжение почти не помогают.
    Для взрослого это честно, для семилетнего — возможно, глухая стена;
    проверить на живом ребёнке, прежде чем смягчать.

## Приложение A. Словарь терминов

| Термин | Значение |
|---|---|
| **Гуардиан** | Монстр, выбранный игроком в забег |
| **Экземпляр** | Конкретный приручённый монстр: вид + грейд + уровень. Коллекция хранит экземпляры |
| **Грейд** | Редкость экземпляра; роллится при встрече, задаёт ×Статы и темп ремикса |
| **Уровень** | Рост силы экземпляра от побед и угощений, 1–10 |
| **Здоровье** | Сквозной ресурс забега, сам не восстанавливается |
| **Настрой** | Здоровье монстра в бою |
| **Дружба** | Постоянный прогресс приручения; своя независимая шкала у каждой пары «вид + грейд» |
| **Поляна** | Одна карточка в свайп-ленте леса |
| **Встреча** | Поляна со случайной сценой: торговец, куст с лутом, бабка |
| **Чарт** | Карта нот для конкретного трека и темповой ступени |
| **Пластинка** | Лутбокс с косметикой |
| **Серебро / Золото** | Игровая / донатная валюта |
| **Семена** | Предмет инвентаря: из него растут фрукты |
| **Зелье** | Предмет инвентаря: лечит в бою через ноту-зелье |
| **Обычный / особый бит** | Нота правой / левой кнопки |
| **Щит** | Сквозной буфер прощения, чинится нотами-щитами |
| **Серия** | Связка нот без пауз; атака в её конце бьёт, если серия чиста |
| **Атака** | Золотая звезда, единственный источник урона по Настрою |
| **Опыт против вида** | Изученность вида: растит урон по нему от встречи к встрече |

## Приложение B. Таблицы баланса

Числа, которыми живут предметы и дроп, вынесены в машиночитаемые таблицы —
их правит дизайнер, а не программист:

- [data/items.json](data/items.json) — **все предметы игры**: имя, описание,
  эффекты, цены. Снаряжение, фрукты (и их семена), зелья, косметика.
- [data/drop_tables.json](data/drop_tables.json) — **все шансы**: типы полян
  и встреч, веса грейдов по глубине, сундук за победу, куст с лутом, бабка,
  косметические сундуки с pity и возвратом за дубли.
- [data/merchant.json](data/merchant.json) — **торговец**: правила ассортимента
  в лесу и на ферме, ротация, цены.
- [data/progression.json](data/progression.json) — **прогрессия**: уровни
  и кривая опыта, множители грейдов, независимые шкалы дружбы, опыт против вида.

Правило: код и `.tres` обязаны совпадать с таблицами. Расхождение — баг,
а не «два мнения о балансе». Автоматическая сверка таблиц с ресурсами —
кандидат в тесты (по образцу `tests/test_shop.tscn`).

Смежные документы: [SHOP.md](SHOP.md) — магазин и регуляторика,
[ACHIEVEMENTS.md](ACHIEVEMENTS.md) — варианты достижений и сезонов.
