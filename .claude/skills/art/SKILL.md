# Арт-пайплайн BEATROOT

Дизайн-контекст — [GDD.md](../../../GDD.md) §11. Инструмент — `tools/artgen/`.
Учёт лицензий — [ASSETS.md](../../../ASSETS.md), запись обязательна для каждого ассета.

**Сам механизм — общий, а не наш.** Он вынесен в личный скилл `genart-pipeline`
вместе с каталогом провалов и картой реализации. Здесь остаётся то, что
специфично для BEATROOT: палитра и её правила, стихии, силуэты, требования GDD.
Если чинишь неработающий промпт или собираешь такой же конвейер в другом проекте —
смотри туда.

## Главный принцип

**Модель рисует живопись — пиксель делает постобработка.**

Не проси у диффузионной модели пиксель-арт. Она выдаёт имитацию с рваной сеткой,
которую дешевле перерисовать с нуля. Генерируй детализированную живопись в высоком
разрешении, а пиксельность получай даунскейлом и квантованием к палитре проекта.

## Палитра и её правило

Два непересекающихся набора в `beatroot_artgen/palette.py`:

- **ENVIRONMENT** — 45 цветов мира. Тёплые земляные тона, низкая насыщенность
- **GAMEPLAY** — 8 цветов. Ноты, шкалы, индикатор замаха. Холодные, насыщенные

> **Ни один цвет из GAMEPLAY не имеет права появиться в окружении.**

Это единственное, что позволяет держать одновременно приглушённый живописный стиль
и мгновенную читаемость ноты. Проверяется тремя метриками:

| Метрика | Порог | Смысл |
|---|---|---|
| Расстояние в OKLab до ближайшего цвета мира | ≥ 0.15 | Цвет не спутать с окружением |
| Насыщенность игрового цвета | ≥ 0.135 | Не растворится в земляном фоне |
| Контраст к типовому фону по WCAG | ≥ 3:1 | Виден на размытом уменьшенном кадре |

Насыщенность проверяется мягко: у голубого в OKLab низкий потолок, выше 0.15 он
не поднимается, оставаясь ярким. Гарантию даёт связка расстояния и контраста.

**При правке палитры всегда прогоняй `artgen palette --check`.** Если конфликт —
чаще правильно двигать цвет мира, а не игровой: игровые связаны конвенцией
(синий = щит, красный = опасность), цвета мира свободны. Так уже решён конфликт
щита с водой — воду увели в бирюзу.

## Конвейер: от манифеста до принятого ассета

Вся графика игры перечислена в [`art/assets.toml`](../../../art/assets.toml) —
это источник правды. Прогон идёт четырьмя ступенями, и каждая следующая дороже
предыдущей, поэтому дешёвые отсеивают брак раньше.

```
  [1] Манифест      art/assets.toml + сверка с data/*.tres.
        │           Монстр в игре без записи об арте — розовый квадрат у игрока.
        ▼
  [2] Генерация     artgen batch: по N сидов на ассет в art/candidates/<id>/.
        │           Резюмируемо: повтор доводит начатое, а не начинает заново.
        ▼
  [3] Ворота        metrics.py, автоматически на каждом кандидате.
        │           Механический брак: невырезанный фон, обрезка краем, крошево,
        │           слияние с поляной. Судить о красоте они не умеют и не должны.
        ▼
  [4] Ревью Клодом  artgen review: контакт-лист на ассет, вердикт командой.
        │           Здесь ловится то, что арифметике недоступно: не тот зверь,
        │           лишний постамент под ним, чужой стиль, страшное лицо.
        ▼
  [5] Ревью глазами artgen gallery -> art/review/gallery.html.
        │           Последнее слово. Страница собирает готовую команду promote.
        ▼
  [6] Перенос       artgen promote: файл в art/<вид>/, sprite_path в .tres,
                    строка в ASSETS.md. Отклонение двигает счётчик попытки.
```

**Отклонение обязано двигать попытку.** Сид детерминирован от id и номера
варианта, и перегенерация без смены попытки выдаёт ровно тот же брак второй раз.
Счётчик двигает `artgen promote --reject`, а `batch` его читает.

### Протокол ревью Клодом (ступень 4)

1. `uv run artgen review --build` — собрать контакт-листы и получить очередь
2. Для каждого ассета из очереди: прочитать лист `art/review/<id>.png` **вместе**
   с текстом очереди — в тексте написано, что сказали ворота
3. Записать вердикт:
   ```bash
   uv run artgen review --record bass_bear=01 --status "принять" --note "чем обосновано"
   ```
   Статусы: `принять`, `принять с правкой`, `переделать`

Лист собран на фоне боя и показывает каждый вариант дважды: увеличенным вчетверо
и в честном размере. Судить только по увеличенному нельзя — в HD-пикселе половина
брака видна лишь в настоящем размере, и наоборот.

Что смотреть, кроме «нравится»:

- **Тот ли это персонаж.** Модель охотно подменяет задание похожим: «sprout child»
  она читает как «девочка с цветами в волосах», и такой ассет спутает игроку
  защитника с героем
- **Нет ли лишнего в кадре.** Постамент под зверем, тень отдельным пятном, вторая
  фигура — ворота это пропускают, а в игре оно поедет вместе со спрайтом
- **Читается ли силуэт в честном размере.** Это то, что увидит игрок на телефоне
- **Годится ли для семи лет.** Клыки, оскал, кровь — мимо (CLAUDE.md §4)

Вердикт Клода и решение человека лежат в **разных файлах** (`verdicts.json` и
`decisions.json`) намеренно: повторный прогон ревью не имеет права отменить то,
что человек уже решил глазами.

## Команды

```bash
cd tools/artgen

# что вообще нужно нарисовать и сходится ли это с данными игры
uv run artgen manifest

# сгенерировать кандидатов по манифесту (можно фильтром)
uv run artgen batch --checkpoint flux1-schnell-fp8.safetensors
uv run artgen batch --kind monster --variants 4
uv run artgen batch --asset bass_bear --force

# контакт-листы и очередь ревью
uv run artgen review --build
uv run artgen review --record bass_bear=01 --status "принять" --note "чистый силуэт"

# страница для ревью глазами
uv run artgen gallery

# перенести принятое в игру
uv run artgen promote --pick bass_bear=01 --reject disco_sprout
```

## Прочие команды

```bash
cd tools/artgen

# проверить палитру, выгрузить art/palette.json и лист art/palette.png
uv run artgen palette

# только проверка, без записи
uv run artgen palette --check

# плейсхолдеры для Фазы 0 (монстры + фрукты + лист превью)
uv run artgen placeholders --preview

# генерация в ComfyUI + автоматическая постобработка
uv run artgen comfy "round mossy forest creature with big eyes" --name moss_pup

# выгрузить workflow файлом, если хочется покрутить руками в ComfyUI
uv run artgen comfy "..." --dump-workflow wf.json

# привести готовую картинку к палитре проекта
uv run artgen pixelize path/to/raw.png art/monster.png --size 96
```

## ComfyUI

Клиент — `beatroot_artgen/comfy.py`, работает по HTTP API (`POST /prompt`,
`GET /history`, `GET /view`). MCP не нужен и не используется.

- Зависимости: `uv sync --extra comfy`
- Хост по умолчанию `http://127.0.0.1:8188`
- Workflow собирается **только из базовых нод** — запустится на чистой установке
  без кастомных пакетов
- Шаблоны промптов — константы `STYLE_POSITIVE` / `STYLE_NEGATIVE`.
  Меняй их, а не отдельные вызовы: консистентность стиля держится на общем шаблоне

**Лицензия модели.** Игра коммерческая. FLUX.1 [dev] и SDXL Turbo **не подходят** —
некоммерческие лицензии. Установлены и годятся: `flux1-schnell-fp8` (Apache 2.0,
основная) и `sd_xl_base_1.0` (Open RAIL++-M, контрольная). Никаких LoRA, обученных
на художниках или франшизах. Состояние моделей — в [ASSETS.md](../../../ASSETS.md).

**Параметры сэмплера задаются профилем модели, а не флагами вызова.**
`comfy.py` держит три профиля — `SDXL`, `FLUX`, `TURBO` — и выбирает по имени
чекпойнта (`profile_for`). Задавать шаги и cfg вслепую нельзя: перепутать cfg 6.5
с cfg 1.0 значит получить кашу или мыло и понять это только на сотне картинок.

**Дистиллированные модели (FLUX schnell, Turbo, Lightning, LCM, Hyper) требуют
другого подхода.** Они работают на cfg ≈ 1.0, а при таком cfg **негативный промпт
почти не действует**. Проверено на Turbo: он дважды проигнорировал требование
белого фона и нарисовал полную лесную сцену. Поэтому:

- для них используется отдельный шаблон `STYLE_POSITIVE_DISTILLED`, где всё
  критичное вынесено в НАЧАЛО позитивного промпта
- вырезка фона не должна зависеть от сговорчивости модели: ставь
  `uv sync --extra cutout`, тогда фон режется сегментацией, а не заливкой от краёв

## Порядок постобработки

Порядок важен, менять нельзя:

1. **Вырезка сегментацией** (`rembg`) — на полном разрешении. Модель сегментации
   должна видеть объект: на 96×96 она уже не видит ничего
2. **Даунскейл** (`Image.BOX`) — усредняет блоки, деталь превращается в цвет пикселя
3. **Запасная вырезка заливкой от краёв** — если сегментация не установлена.
   Заливка именно от краёв, а не отбор по цвету: отбор пробил бы дыры на месте
   бликов внутри существа. Идёт после даунскейла, потому что на 96×96 заливка
   мгновенна, а на 1024×1024 сходится долго
4. **Квантование** к палитре мира по расстоянию в OKLab

Полупрозрачные края режутся жёстко по порогу: мягкая альфа читается как размытие
и убивает ощущение пикселя.

**Прозрачные и стеклянные существа — известная слабость шага 1.** Сегментация
уверенно съедает студенистого монстра целиком, и на выходе получается пустой кадр.
Ворота это ловят (`coverage`), но исправляется оно только перегенерацией:
`artgen promote --reject <id>` и следующий прогон.

## Плейсхолдеры

`artgen placeholders` строит существ из эллипсов и красит рампами палитры.
Форма детерминирована именем через SHA-256 — **не через `hash()`**, он
рандомизируется между запусками, и монстр менял бы облик при каждом старте.

Пять силуэтов (`biped`, `quadruped`, `flyer`, `blob`, `serpent`) соответствуют
шаблонам ригов из GDD §11.2. Жанр монстра задаёт рампу — по цвету видно, с кем дело.

## Что генерации не отдаётся никогда

UI, ноты, индикаторы щита и замаха рисуются вручную. От их читаемости зависит
честность боя — игрок должен различать их безошибочно, а генерация этого не гарантирует.

В манифесте они помечены `generated = false` и всё равно перечислены: галерея
обязана показывать полный состав графики игры, включая ещё не сделанное. Туда же
попали танцевальные эмоуты — это анимации на риге, а не картинки (GDD §11.2).

## Тесты

```bash
cd tools/artgen && uv run --extra test pytest tests -q
```

Входят в общий `./run_tests.sh`. Ворота проверяются **мутацией**: на каждую
проверку заведена картинка, сломанная ровно её способом, и тест утверждает, что
падает именно эта проверка. Проверено обратной мутацией — ослабление порога
в `metrics.py` валит ровно тот тест, который за него отвечает.

Меняя порог, прогоняй тесты: они держат его с обеих сторон, а не только снизу.
